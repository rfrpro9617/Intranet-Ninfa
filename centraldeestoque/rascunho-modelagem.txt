Tabela de saldo agregado; sempre atualizada pela mesma transação que grava a movimentação.

movimentacoes — histórico imutável (append-only) | id | uuid PK | | data | timestamptz NOT NULL default now() | | material_id | uuid FK → materiais NOT NULL | | tipo | enum tipo_movimentacao ('entrada','saida','devolucao') NOT NULL | | quantidade | numeric(14,3) NOT NULL CHECK (> 0) | | setor_id | uuid FK → setores (NULL apenas para entrada) | | responsavel_id | uuid FK → auth.users | | responsavel_nome | text NOT NULL (snapshot histórico) | | pedido_id | uuid FK → pedidos (opcional, só em entrada) | | observacao | text | | created_at | timestamptz |

Constraints:

CHECK (tipo = 'entrada' OR setor_id IS NOT NULL) — saída e devolução exigem setor.
CHECK (tipo <> 'entrada' OR setor_id IS NULL)
Sem UPDATE/DELETE via RLS (histórico permanente).

Usuários e permissões
profiles: id (uuid PK = auth.users.id), nome, cargo, created_at. user_roles: id, user_id FK → auth.users, role enum app_role ('admin','almoxarife','leitor'), UNIQUE(user_id, role) — nunca em profiles; leitura via função has_role() security definer.

Regras que devem viver no banco, não só na UI
Três funções (registrar_entrada, registrar_saida, registrar_devolucao) em plpgsql, SECURITY DEFINER, transacionais:

Entrada: estoque_central += qtd; se vinculada a pedido, incrementa quantidade_recebida e recalcula situação (parcialmente_recebido / recebido); insere gasto.
Saída: valida quantidade <= estoque_central (senão exceção), decrementa central, faz upsert em posses somando, atualiza ultima_saida.
Devolução: valida quantidade <= posses.quantidade do setor, decrementa posse, incrementa central.
Os CHECK (>= 0) em estoque_central e posses.quantidade são a rede de segurança final contra saldo negativo.

Índices sugeridos: movimentacoes(material_id, data desc), movimentacoes(setor_id), movimentacoes(tipo, data desc), posses(setor_id), pedido_itens(pedido_id), gastos(data desc).
